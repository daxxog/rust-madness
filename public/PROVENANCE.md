# Provenance

What is original, where it came from, and what is derived. Every
statement below is either computed from the shipped files, sourced from the
original's own embedded credits, or describes a reproducible derivation.

## mad.jar — the original applet archive

- Original distribution URL: `http://www.radicalplay.com/madness/mad.jar`
  (archived host page captured 2007-10-09).
- SHA-256, computed from the shipped `mad.jar`:
  `70e54d44c65631f3eb014f57398851502cda75dde173d4e06ca37dcd37429f0b`
- SHA-1: `8da705cab492cf07722f661c2e3bd8380a3350f9` — base32-encoded the
  same way the Wayback Machine's CDX digests are, it is
  `RWTQLSVUSLHQO4RPMYOC4O6YHAFDGUHZ`, which **equals the CDX digest of
  every 200-OK capture of that URL**: 2006-05-05, 2006-10-25 and
  2007-07-02. The shipped jar is byte-identical to what the site
  served across that whole span.
- Acquisition: obtained from the Wayback Machine during this project's
  recovery pass. No permission has been sought from the rights
  holder; see `NOTICES.md` for the preservation stance.
- The "2006" dating is the earliest archival record of these exact bytes
  (the Wayback capture of 2006-05-05, digest-matched); no date is
  encoded in the jar.

## assets/ — server-side game data (70 files)

The 70 files under `assets/` (models, stages, music and sounds) are original
game data recovered from the game's HTTP server via archived captures; the
per-file capture timestamps, byte counts, SHA-256 digests and byte-identity
checks against those captures are in `assets/PROVENANCE.md`, which ships with
the tree.

- Recovered by this project's own `tools/fetch-assets.sh`: it queries the
  Wayback Machine's CDX API for each resource's captures, takes the
  earliest 200-OK one (closest to the applet era), downloads the
  original bytes via the `/id_/` memento (no wayback decoration), and
  proves byte-identity by re-encoding each file's SHA-1 in the CDX's
  base32 alphabet and comparing it against the archive's own digest.
  `assets/PROVENANCE.md` is regenerated by that script on every run.
- Acquisition: the archived captures of the same
  `radicalplay.com/madness` server tree that served the applet. No
  permission has been sought from the rights holder; see `NOTICES.md`.

## `reference/external/catb0t/OBJ/mycars/Simple Car.rad` — third-party test fixture

- Source: **catb0t's public decompilation of the standalone game**,
  `github.com/catb0t/need-for-madness-source` (`OBJ/mycars/` in that tree);
  cited in `notes/ARCHITECTURE.md` as the source of the standalone build.
  This is a **development car model** from that project, not output of this
  project's decompiler and not part of the applet's own distributed content.
- Role: a byte-parser fixture — `tests/java/TContO.java` (`realCar`) exercises
  the original car-loading format against these exact bytes, and the Rust
  mirror `nfm-core`'s `mirror::mirror_suite` maps the same pin one-to-one.
  Both gates need the file at this path; the rest of `reference/` is
  regenerated in CI from `mad.jar`.
- SHA-256, computed from the shipped file:
  `5d319a4cb09ec6ec37bb9d531ed4212367d6ee3c01c3ae835a1fe0c7a97b2d91`
  (2,702 bytes).
- Credit: the catb0t project and the original Need for Madness authors; see
  `NOTICES.md`. No rights are asserted over this file by this project.

## Derived chains (reproducible; not authored content)

- **Decompiled Java sources (`reference/vineflower/`) are regenerated, not
  shipped.** CI rebuilds them from `mad.jar` with **Vineflower 1.10.1**, pinned
  as `ARG VINEFLOWER_VERSION=1.10.1` in `tools/Dockerfile` (the same version is
  recorded in the private tree's decompiler notes). The toolchain lives in
  `tools/`: `tools/decompile.sh` builds the image and
  `tools/container-decompile.sh` runs the pinned decompilers against `mad.jar`
  (podman required). CFR 0.152 and Procyon 0.6.0 are cross-checks; the
  bytecode disassembly is produced with `javap` (JDK 21 inside the image).
  The decompiled tree is generated output and is never edited by hand.
- **`resources.pack` is derived from `assets/` and
  `tests/fixtures/xtfont-atlas/` by `tools/pack.sh`.** It is gitignored and
  never committed; `crates/nfm-core/build.rs` embeds it into release binaries,
  so the shipped executable needs no resource files at runtime. Re-run
  `tools/pack.sh` after changing anything under `assets/` or the atlas.
- **This repository is derived too.** `tools/public-export.sh` rebuilds the
  public tree from the private source of truth; edit the source, not the
  exported result.
